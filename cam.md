# Полный конспект по теории 3D-графики и Vulkan

Этот документ описывает, как работает 3D-приложение: от создания вершин до финального пикселя на экране, включая математику освещения и архитектуру Vulkan.

## 1. Геометрия и Вершины

### Как создается форма?
Геометрия не загружается из файла, а генерируется процедурно (математически) в коде (функция createConeMesh).

*   Вершина (Vertex): Атомарная единица 3D-графики. В нашей программе она содержит три атрибута:
    1.  Position (`vec3`): Координаты X, Y, Z в локальном пространстве.
    2.  Normal (`vec3`): Вектор, перпендикулярный поверхности. Нужен для расчета света (куда смотрит грань).
    3.  UV (`vec2`): Текстурные координаты.
*   Индексы (Indices): Список чисел, указывающий, в каком порядке соединять вершины. Позволяет не дублировать вершины, которые принадлежат нескольким треугольникам сразу (например, вершина конуса).

### Что такое UV-координаты?
Это способ развернуть 3D-поверхность на 2D-плоскость (аналогия: фантик от конфеты).
*   U: Горизонтальная ось (0..1).
*   V: Вертикальная ось (0..1).
Даже без текстур UV можно использовать для процедурных эффектов.

## 2. Пространства Координат (Coordinate Spaces)

Чтобы точка из 3D-мира попала на 2D-экран, она проходит цепочку трансформаций (умножения на матрицы):

1.  Local Space (Локальное пространство):
    *   Объект находится в центре (0,0,0). Ему все равно, где он в мире.
    *   *Операция:* Умножение на Model Matrix.
2.  World Space (Мировое пространство):
    *   Все объекты расставлены по своим местам, повернуты и масштабированы.
    *   *Операция:* Умножение на View Matrix.
3.  View Space (Пространство Вида / Камеры):
    *   Весь мир поворачивается так, чтобы Камера оказалась в центре (0,0,0) и смотрела вдоль оси Z.
    *   *Операция:* Умножение на Projection Matrix.
4.  Clip Space (Пространство Отсечения):
    *   Здесь применяется перспектива (дальние объекты уменьшаются).
    *   Всё, что не попадает в видимый "куб" (фруструм), отрезается.

## 3. Теория Камеры

В 3D-графике нет физической камеры. Мы создаем иллюзию движения, сдвигая весь мир в противоположную сторону.

### View Matrix (Матрица Вида)
Это обратная матрица к матрице трансформации камеры.
*   Если камера летит вперед (+Z), мы сдвигаем мир назад (-Z).
*   Если камера поворачивается направо, мир поворачивается налево.

Формула:
$$View = Inverse(Translation \times Rotation)$$

### Управление камерой (FPS стиль)
*   Pitch (Тангаж): Вращение вверх-вниз (вокруг оси X). Ограничиваем до 89 градусов, чтобы не сломать шею.
*   Yaw (Рыскание): Вращение влево-вправо (вокруг оси Y).
*   Векторы Forward (куда смотрим) и Right (боковой стрейф) рассчитываются через синусы и косинусы этих углов.

## 4. Освещение: Модель Блинна-Фонга (Blinn-Phong)

Это классическая модель, улучшенная версия модели Фонга. Она состоит из суммы трех компонентов:

$$Light = Ambient + Diffuse + Specular$$

### 1. Ambient (Фоновое / Рассеянное)
*   Суть: Свет, который есть везде. Имитирует многократное переотражение лучей от стен.
*   Результат: Тени не абсолютно черные, а слегка подсвечены.
*   Формула: $K_{ambient} \times Color_{albedo}$

### 2. Diffuse (Диффузное)
*   Суть: Основной цвет поверхности, зависящий от угла падения света.
*   Математика: Скалярное произведение (Dot Product) вектора Нормали ($N$) и направления на Свет ($L$).
    *   Если угол 0° (свет перпендикулярен) -> яркость 1.0.
    *   Если угол 90° (свет скользит) -> яркость 0.0.
    ### 3. Specular (Блик / Зеркальное)
*   Суть: Яркое пятно отражения самого источника света.
*   Отличие Блинна-Фонга от Фонга:
    *   Вместо расчета отраженного вектора (Reflection), считается Halfway Vector ($H$) — вектор посередине между взглядом ($V$) и светом ($L$).
    *   Считается угол между Нормалью ($N$) и этим вектором $H$. Это быстрее и дает более мягкие блики.
*   Параметры:
    *   Shininess (Блеск): Степень двойки (32, 64...). Чем выше, тем меньше и острее блик (металл/вода). Чем ниже, тем блик шире (пластик/резина).
    *   Specular Color: Цвет блика (обычно белый для диэлектриков, цветной для металлов).

## 5. Типы источников света

### 1. Directional Light (Направленный)
*   Аналог Солнца.
*   Лучи параллельны, позиция источника не важна, только направление.
*   Нет затухания.

### 2. Point Light (Точечный)
*   Аналог лампочки.
*   Свет исходит из точки во все стороны.
*   Затухание (Attenuation): Подчиняется Закону обратных квадратов. Яркость падает пропорционально квадрату расстояния ($1/distance^2$).

### 3. Spotlight (Прожектор)
*   Аналог фонарика.
*   Точечный источник, ограниченный конусом.
*   Cutoff: Угол внутреннего конуса (где свет яркий).
*   Outer Cutoff: Угол внешнего конуса (где свет плавно исчезает).
*   В шейдере используем smoothstep или clamp для мягкого края.

## 6. Архитектура Vulkan (Как это работает внутри)

Vulkan — это API низкого уровня. Чтобы нарисовать треугольник, нужно явно описать все этапы.

### Графический Конвейер (Graphics Pipeline)
Запеченное состояние GPU, создается в initialize.
1.  Input Assembler: Собирает вершины из буферов.
2.  Vertex Shader: Программа для каждой вершины. Переводит координаты из 3D в 2D-экран (умножает на матрицы).
3.  Rasterizer: Превращает треугольники в пиксели (фрагменты). Интерполирует данные (цвета, UV) между вершинами.
4.  Fragment Shader: Программа для каждого пикселя. Считает освещение и цвет.
5.  Depth Test: Проверяет Z-буфер, чтобы не рисовать то, что скрыто за стеной.
6.  Color Blending: Смешивает цвета (или просто перезаписывает).

### Передача данных (CPU -> GPU)
*   Uniform Buffers (UBO): Для небольших данных, которые не меняются внутри кадра (Матрицы камеры, параметры материала). Быстрые, но мало памяти.
*   Storage Buffers (SSBO): Для больших массивов данных переменной длины (наш массив источников света LightSource lights[]). Медленнее, но огромные.
*   Descriptor Sets: "Мостик", который говорит шейдеру, где в памяти лежат наши буферы.

### Отрисовка (render)
1.  Command Buffer: Мы не рисуем сразу. Мы записываем команды ("Привяжи пайплайн", "Привяжи буфер", "Рисуй") в буфер команд.
2.  Submit: Отправляем буфер на выполнение видеокарте.

## 7. Логика программы (Cheat Sheet для ответа)

Если препод спросит "Как у тебя реализовано...":

*   Вращение объектов?
    *   "В функции update я меняю угол вращения модели, умножая скорость на дельту времени. Затем формирую Model Matrix."
*   Свет?
    *   "Я использую SSBO для передачи массива структур LightSource в шейдер. Во фрагментном шейдере я прохожу циклом по всем источникам и суммирую вклад по модели Блинна-Фонга."
*   Камера?
    *   "Я обрабатываю ввод с клавиатуры/мыши через ImGui IO, обновляю углы Эйлера (Pitch/Yaw) и позицию, затем строю матрицу вида как инверсию матрицы трансформации камеры."
*   Почему `cullMode = NONE`?
    *   "Я отключил отсечение задних граней, чтобы избежать проблем с исчезновением геометрии при инверсии осей или неправильном порядке вершин, и гарантированно видеть объекты."
